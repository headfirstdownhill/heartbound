# Heartbound for Android

`heartbound.apk` is the installable game. Copy it to the phone, tap it, and
allow installing from unknown sources when asked. Android 7.0 (API 24) or newer.

The app is one full-screen WebView wrapped around the same `heartbound.html` the
browser runs. Nothing else. That is the whole design: the game is already a
self-contained page, so the Android side only has to show it and get out of the
way.

## What it does and does not do

- **Works offline.** Phaser is vendored into `assets/` instead of being pulled
  from a CDN at load, and `build.ps1` rewrites the script tag on the way in. The
  phone can be in flight mode.
- **Asks for no permissions.** There is no `<uses-permission>` in the manifest
  at all, because nothing is ever fetched, stored outside the app, or read off
  the device.
- **Keeps the screen on** while playing, and locks to portrait.
- **Remembers the inventory.** The unlock lives in `localStorage`, which needs
  `setDomStorageEnabled(true)` on the WebView — off by default, and silently
  loses the save if forgotten.
- **Back exits**, as standard. There is no mid-run save, so a back gesture
  during a run costs the run.

## Rebuilding

Regenerate `heartbound.html` in the project root first if you have touched
anything under `js/`, then:

```bash
powershell -ExecutionPolicy Bypass -File android\build.ps1
```

It needs, and finds automatically:

| | Where it looks |
|---|---|
| JDK 17+ | `%LOCALAPPDATA%\Programs\jdk-17` — override with `-Jdk` |
| Android SDK | `%LOCALAPPDATA%\Android\Sdk` — override with `-Sdk` |

From the SDK it uses the **highest installed** build-tools and platform, so an
SDK update will not strand it on a version that has been removed. No Gradle, no
Node, no Android Studio project: the app is one Java file, and a build system
for that would be several hundred megabytes of machinery to compile it.

The pipeline is `aapt2 compile` → `aapt2 link` → `javac` → `d8` → insert
`classes.dex` → `zipalign` → `apksigner`.

## The signing key

`heartbound.keystore` is generated on the first build and then reused. It is
self-signed with a known password, which is fine for sideloading and useless for
anything else.

**Keep it.** Android refuses to install an update signed with a different key,
so deleting it means uninstalling the app from the phone before the next build
will go on.

## The icon

Generated by `tools/make_icons.py` from the same heart grid the game draws, in
keeping with the rest of the project having no image files. It writes the PNGs
by hand out of `zlib`, so it needs nothing installed. `build.ps1` runs it only
when the icons are missing; delete `res/mipmap-*/ic_launcher.png` to force it.

## Layout

```
AndroidManifest.xml   package, portrait lock, launcher activity, no permissions
build.ps1             the whole build
src/                  MainActivity — the WebView and its settings
res/values/           app name, and a full-screen theme painted the game's black
res/mipmap-*/         generated launcher icons
assets/               phaser.min.js, the mp3s, and heartbound.html staged by the build
tools/make_icons.py   icon generator
heartbound.keystore   signing key — do not delete
heartbound.apk        the build output
```

## Two things this build gets deliberately right

**Assets are flat.** The mp3s sit directly in `assets/`, not in `assets/audio/`,
and the build rewrites `AUDIO_BASE` in the staged html to match. That is not
tidiness: aapt2 on Windows writes nested asset paths into the apk with
backslashes, so the files arrive as `assets/audio\thing.mp3`, and AssetManager
looks them up with forward slashes and never finds them. The app then runs in
silence with nothing else visibly wrong.

**Nothing repacks the apk afterwards.** An earlier version of this build fixed
those backslashes by rebuilding the zip in PowerShell and re-signing. It looked
fine — it aligned, it verified, `aapt2 dump badging` read it — and it would not
install: .NET Framework's `CompressionLevel.NoCompression` still writes
deflate-method entries rather than stored ones, and anything targeting SDK 30 or
newer must have `resources.arsc` stored uncompressed. Android rejects it with
`INSTALL_PARSE_FAILED_RESOURCES_ARSC_COMPRESSED`, which reaches the phone as a
bare "App not installed".

If you ever change the packaging, that is the thing to check:

```bash
powershell -Command "Add-Type -AssemblyName System.IO.Compression.FileSystem; ([IO.Compression.ZipFile]::OpenRead('android\heartbound.apk')).Entries | Where-Object { $_.FullName -eq 'resources.arsc' } | Select-Object FullName,Length,CompressedLength"
```

`Length` and `CompressedLength` must be equal. If they differ, the apk will not
install on any modern phone no matter what the signature checks say.

## Installing it

Play Protect will warn that the developer is unknown — that is what self-signed
means, and "Install anyway" is the answer. If it still refuses, uninstall any
older Heartbound first: Android will not replace an app whose signing key does
not match, and that also surfaces as "App not installed".
